# Internationalisation (i18n)

Every string visible to the user **MUST** go through `t()` from `useTranslation`. No hardcoded strings in JSX. Supported locales: English (`en`) and Vietnamese (`vi`).

## Translation File Structure

Locale files live at:

```
src/app/i18n/locales/
  en.json   ← English (source of truth)
  vi.json   ← Vietnamese
```

Keys are nested by domain namespace:

```json
{
    "common": { "save": "Save", "cancel": "Cancel" },
    "admin": {
        "foodForm": { "name": "Name", "price": "Price (₫)" },
        "customisationManager": { "title": "Customisation Groups" }
    },
    "customer": {
        "foodDetail": { "addToCart": "Add to cart" }
    }
}
```

---

## Rules

- **MUST** — every user-visible string uses `t()`. No hardcoded text in JSX.
- **MUST** — add the key to **both** locale files (`en.json` and `vi.json`) in the same commit.
- **Rule** — check `common.*` first before adding a new key. Reuse over duplication.
- **Rule** — dynamic values use `{{variable}}` interpolation — never string concatenation.
- **Rule** — translation keys are camelCase. File path follows the page/feature structure.

---

## useTranslation Usage

```typescript
import { useTranslation } from 'react-i18next';

function MyComponent() {
    const { t } = useTranslation();

    return <h1>{t('admin.foodForm.title')}</h1>;
}
```

- ✅ Call `useTranslation()` once per component
- ❌ Pass `t` down as a prop — every component fetches its own `t`
- ❌ Hardcoded strings: `<h1>Food Details</h1>`

---

## Key Naming Convention

| Context                 | Namespace              | Example key                                     |
| ----------------------- | ---------------------- | ----------------------------------------------- |
| Shared across the app   | `common.*`             | `common.save`, `common.cancel`, `common.delete` |
| Admin portal feature    | `admin.<feature>.*`    | `admin.foodForm.name`                           |
| Customer-facing feature | `customer.<feature>.*` | `customer.foodDetail.addToCart`                 |
| Auth screens            | `auth.*`               | `auth.login.emailLabel`                         |

Keys within a namespace use camelCase: `groupLabel`, `deleteGroupTitle`, `required`.

---

## Interpolation

Use `{{variable}}` placeholders for dynamic content. Pass values as the second argument to `t()`.

```json
// en.json
{
    "admin": {
        "foods": {
            "deleteFoodConfirm": "Are you sure you want to delete \"{{name}}\"? This action cannot be undone."
        }
    }
}
```

```typescript
// ✅ Good: interpolation
t('admin.foods.deleteFoodConfirm', { name: food.name })
// ❌ Bad: string concatenation
`Are you sure you want to delete "${food.name}"? This action cannot be undone.`;
```

## Examples

### Component with multiple translated strings

```typescript
import { memo } from 'react';
import { useTranslation } from 'react-i18next';

import { Button } from '@/uis/button';

interface DeleteConfirmProps {
    name: string;
    onConfirm: () => void;
    onCancel: () => void;
}

function DeleteConfirm({ name, onConfirm, onCancel }: DeleteConfirmProps) {
    const { t } = useTranslation();

    return (
        <div>
            <p>{t('admin.foods.deleteFoodConfirm', { name })}</p>
            <Button variant='destructive' onClick={onConfirm}>
                {t('common.delete')}
            </Button>
            <Button variant='outline' onClick={onCancel}>
                {t('common.cancel')}
            </Button>
        </div>
    );
}

export default memo(DeleteConfirm);
```

### Adding a new key (checklist)

1. Add to `en.json` under the correct namespace.
2. Add the Vietnamese translation to `vi.json` in the same commit.
3. Use `t('namespace.key')` in the component.
4. If the key is shared across features, use `common.*`.
